# RP-677 scenarios

Rows of the [scenario matrix](../../visibility.md#scenario-matrix-becomes-the-automated-visibility-test-suite) added under RP-677, in its setup (Project "Tower", C1, C2, K1, OR, OW).

| # | Scenario | Who | Expected |
|---|---|---|---|
| RP-677-1 | K1 raises Snags on C1 (Building A, one with a photo) and on C2 (Building B, one with a photo); C1's PM, C2's engineer and K1 each ask for a Snag report (all items, the chosen ones, a List filter), in English and Arabic; a colleague, K1, C2 and a Member of no Project ask after C1's report by id | C1 PM; C2 engineer; K1 manager; C1 engineer | A report holds only the items its asker reads through the Snag List's own Export read (C2's holds none of C1's, C1's none of C2's), narrowed to the ids chosen: an id the asker does not see is dropped, and a request left with nothing is the plain 404. Each item's first photo is drawn only where row-level security on Documents shows it to the asker. Step Age is in weeks, with no due date or "overdue"; an Arabic report is right to left with Latin digits and the Document Number left to right. A report is its asker's alone: anyone else, even in the same Company, and a made-up id get the plain 404 for the report and its file link, and it is found under its own Project's URL only. The database holds the photo rule on its own (RP-1003): `app.request_snag_report` refuses a photo key that is not a Document the asker reads (another Company's Draft photo, a waiting After photo, a removed one, a key that is no Document), whoever calls it. It holds the rows rule on its own too (RP-1078): each row names its item, and must be exactly what the Snag List shows the asker for it (Document Number, Subject, Type, Trade, Location, Stage, who it is with and Step Age, as `app.work_items_seen` gives them), with the Project's own name; a row of an item they do not see, or any other field, is refused. Seam 1 `apps/api/test/snag-report.test.ts`; seam 2 `packages/db/test/snag-report-rls.test.ts` |
| RP-677-2 | A Member of the Project asks for a report; a colleague on it, a Member of no Project and the app role read the table and the state by id; the worker reads and saves the job | C1 PM; colleague; outsider | The `snag_report` table (the snapshot) is read by no one through the app role; `app.snag_report_state` answers its asker alone (preparing, then ready with the file's key) and nothing to anyone else; a Member of no Project cannot ask; the job row holds the report's id only; only the worker, with no Member set, reads the snapshot (`app.snag_report_job`) and saves the PDF, once. Seam 1 `apps/api/test/snag-report.test.ts` (a Member of no Project asks for none and reads none by id), seam 2 `packages/db/test/snag-report-rls.test.ts` |
