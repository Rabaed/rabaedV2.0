# RP-23 scenarios

Rows of the [scenario matrix](../../visibility.md#scenario-matrix-becomes-the-automated-visibility-test-suite) added under RP-23, in its setup (Project "Tower", C1, C2, K1, OR, OW).

| # | Scenario | Who | Expected |
|---|---|---|---|
| RP-23-1 | K1's PM issues Code A on C1's MAR; the record is made | C1 PM; K1 engineer; OR (oversight); C2 | C1, K1 and OR download the same sealed record from the item, the List's row menu and the item's folder, naming C1's and K1's actors with their Signatures and both Companies' Stamps (V7); C2 gets the 404 everywhere. The record job's read names each actor with their Company and the Signature their event recorded (never a newer one), the Stamps in force at the close, and never C2 (seam 1 `apps/api/test/documental-record.test.ts`, `documental-record-signatures.test.ts`; seam 2 `packages/db/test/documental-record-facts-rls.test.ts`) |
| RP-23-2 | K1's engineer recommends Code C, K1's PM issues Code A; on another item the Owner sends a Code B back and confirms the Code D that follows | C1 PM | The record's card for the engineer reads "Reviewed" with no Code, and no C appears anywhere in the PDF or in the Record Data inside it but among the Final decision's chips (V5, V7). Neither record holds a Return or its reason, an Internal Note, a Recommended Code, the Code the Owner sent back with its Remarks, Comments or Recommendation, or the Draft's start, in the pages or the Record Data. The record job's read gives every move but answers and Remarks only for a shared one, so none of those either (seam 1 `apps/api/test/documental-record-signatures.test.ts`; seam 2 `packages/db/test/documental-record-facts-rls.test.ts`) |
| RP-23-3 | C1's PM downloads a Working Copy while K1 reviews the MAR | C1 PM; K1 PM | Both get the same PDF: watermarked, unsealed, no Verification Code, K1 and C1 by Company name only, no person and no Signature (V14). What the worker prints holds no Member's id or name, no Signature, Stamp, logo or Verification Code, and every viewer is given the one copy (seam 1 `apps/api/test/working-copy.test.ts`; seam 2 `packages/db/test/working-copy-rls.test.ts`; its content, RP-1083-3) |
| RP-23-4 | A visitor not signed in scans the record's QR, then types its Verification Code without the Document Number | Anyone | The QR shows: genuine, Document Number, Subject, Project, outcome, sealed date, signers' names, Positions and Companies; no Document, answer or live item. The code alone is refused exactly as a wrong code |
| RP-23-5 | C1's Company has no Stamp; C1's engineer, with a Signature, opens Send for Review on their Draft, whose Form isn't complete; a Member of another Company with no Stamp tries the same Transition; C1's Authorized Person then adds the Stamp | C1 engineer; C1 PM (no Transition to take); C2 | The item read says a Stamp is needed, so the message shows before any Action Form, naming only C1 and saying its Authorized Person must add it (the Authorized Person gets Add Stamp instead). The PM is asked for nothing. C2 gets the plain 404. Once the Stamp is added the engineer takes it; no logo is needed, and the record job's read gives that Stamp and no logo (seam 1 `apps/api/test/company-stamp.test.ts`; seam 2 `packages/db/test/documental-record-facts-rls.test.ts`) |
