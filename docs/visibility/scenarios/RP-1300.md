# RP-1300 scenarios

Rows of the [scenario matrix](../../visibility.md#scenario-matrix-becomes-the-automated-visibility-test-suite) added under RP-1300: a Revision Draft keeps its chain's base Document Number from the start (owner's decision 2026-11-13, UAT SUB-15; workflow-engine.md §8; GLOSSARY › Revision). Their setup: Project "Tower", C1 the Contractor (its Authorized Person is the Project Admin) with an engineer and a PM, K1 the Consultant (its manager issues the Code) and an Owner Representative, all covering every Trade and Location. C1's MAR "Cable trays" is Submitted and closed at Code C by K1, and C1's engineer creates its Rev 1, a Draft. Seam 1 `apps/api/test/rp-1300-revision-draft-number.test.ts`.

Open point, raised on RP-1300 for Main 2: the search text holds the base number whoever searches, while the shown `baseNumber` needs the reader to see the original too (`app.revision_chain`). Search answers only items the reader sees, and a Revision Draft is seen only within the raiser's Company, which raised the original, so no other Company is reached. A Member of that Company who sees the Draft but not the original (a narrower Member Visibility than the Draft's Trade or Location) would find the Draft by a base number the Draft does not show them; that number reaches them anyway at the Submit ("… Rev 1").
