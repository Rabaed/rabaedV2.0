# RP-952 scenarios

Rows of the [scenario matrix](../../visibility.md#scenario-matrix-becomes-the-automated-visibility-test-suite) added under RP-952 (ADR 0028: only the Host Company's Project Admin withdraws a Participant; visibility.md "A Participant's withdrawal"; workflow-engine.md §9), in their setup: Project "Tower", C1 the Host Company (its Authorized Person is the Project Admin), C2 a second Contractor, K1 the Consultant (an engineer and a manager), and the Project Admin of another Project. Seam 1 `apps/api/test/rp-952-visibility.test.ts`, seam 2 `packages/db/test/rp-952-visibility-rls.test.ts`.

| RP-952-1 | C1's Project Admin withdraws C2, which has one item Submitted and held by K1, one Draft, and (seam 2) a Draft Revision of an item closed at Code C | C1 Project Admin, engineer and PM; K1 engineer and manager; C2's Members | The preview gives counts only: 1 item to be Cancelled, 0 Steps to become Vacancies; never the Drafts, which no other Company ever saw, so the Host Company does not learn how many there are. The Submitted item is Cancelled by Rabaed: one shared `cancelled` event with no Member and `left_participant_id` C2, outcome `cancelled`, at its Version's Cancelled Step, its open Steps `done` at its `closed_at` (RP-955, `app.held_at_close`), and its Documental Record queued. K1, who held it, reads it closed and Cancelled, and the event. The Draft and the Draft Revision, which K1 and C1 never read, are Cancelled with no Record. After the withdrawal nobody reads them, and C2's Members read neither item nor the Project |
| RP-952-2 | Who may withdraw, and who may preview | C1 Project Admin; C1 engineer and PM (not Project Admins); K1's and C2's Authorized Persons; another Project's Project Admin | Only C1's Project Admin previews or withdraws.
