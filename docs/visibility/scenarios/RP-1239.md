# RP-1239 scenarios

Rows of the [scenario matrix](../../visibility.md#scenario-matrix-becomes-the-automated-visibility-test-suite) added under RP-1239 (rename and deactivate a Project's Trades and Locations; "Archive" on screen). Setup: a Project of C1's (Contractor, its creator and Project Admin), with K1 as its Consultant; seam 2 adds OW (an Owner), C2 (another Contractor, covering Building B only) and OT, the Authorized Person and Admin of another Company's own Project. Seam 1 adds C3, another Company's Project Creator with its own Project.

| # | Scenario | Who | Expected |
|---|---|---|---|
| RP-1239-1 | Rename, deactivate or reactivate a Trade or Location (`PATCH /v1/trades/:valueId`, `PATCH /v1/locations/:valueId`, `app.update_dimension_value`) | The Project Admin; the Admin's own Company's other Project Members; every other Company's Authorized Person and Project Members on the Project; another Project's Admin | Only the Project Admin changes it: the name only (the code never changes); the General Trade is renamed but never deactivated (`general_trade`); a Location is deactivated with every Location below it, and one below a deactivated Location is not reactivated (`parent_deactivated`). Everyone else gets the 404 that names nothing (db: `not_found`) and nothing changes, as for a made-up id or a value of the other dimension (seam 1: `apps/api/test/rp-1239-visibility.test.ts`; seam 2: `packages/db/test/rp-1239-visibility-rls.test.ts`) |
| RP-1239-2 | A Work Item and a grant on a deactivated Location (the item read; `app.participant_covered_values` with each value's status) | The item's own Company and those who saw it before; every Company it was hidden from; the Participant's own Company and the Project Admin for the covered values; everyone else | Nobody loses or gains Visibility: the item stays with those who saw it and hidden from everyone else, and the Participant's grant still covers the deactivated value, read (as deactivated) by its own Company and the Project Admin only (seam 1 and seam 2 as above) |
| RP-1239-3 | Pick a deactivated value for a new Work Item or a grant (`POST /v1/projects/:projectId/work-items`, `PUT …/visibility`, `app.check_work_item_built_ins`, `app.set_participant_visibility`, `app.set_member_visibility`) | The Project Admin; a Participant's Authorized Person; a Project Member raising an item | Refused (`value_not_found`): a new item never takes it (an item keeps its own), and a grant lists it only while it already covers it, so a grant never widens onto it (seam 1 and seam 2 as above) |
| RP-1239-4 | The Visibility Gap with deactivated values (`GET /v1/projects/:projectId/visibility-gap`, `app.project_visibility_gap`) | The Project Admin; everyone else | A deactivated value is in the gap only while a Work Item uses it, with its status; the gap stays the Project Admin's only, the 404 that names nothing for everyone else (RP-1156-1) (seam 1 and seam 2 as above) |
